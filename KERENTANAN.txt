BAGIAN 0 — RINGKASAN EKSEKUTIF
--------------------------------------------------------------------------------

Estate siroheree.com terdiri dari:

  - Frontend       : Vercel (deployment alias siroheree-web.vercel.app)
  - Edge           : Cloudflare (DNS, MX, CDN)
  - Backend mail   : Cloudflare Worker + D1  (mail-api.siroheree.com)
  - Backend lisensi: Cloudflare Worker + D1  (farm-api.siroheree.com)
  - File storage   : Cloudflare reader (files.siroheree.com)

Ker rentanan paling fatal:

  1. Master admin key `siro123admin` TER-HARDCODE di JavaScript client-side
     (superadmin.html), dipakai untuk 3 layanan sekaligus.
  2. Alias `siroheree-web.vercel.app` TIDAK terproteksi checkpoint Vercel,
     sehingga seluruh panel admin bisa diakses tanpa tantangan.
  3. Backend menerima key itu tanpa verifikasi identitas/role/session.
  4. Endpoint `POST /api/admin/users/{id}/update` bisa menimpa password user
     mana pun -> ACCOUNT TAKEOVER PENUH.
  5. Voucher `kind` tidak divalidasi -> user 1000 mailbox, 10 tahun.

Total temuan: 22 (5 Critical, 6 High, 6 Medium, 5 Low/Info)

BAGIAN 2 — DAFTAR KERENTANAN LENGKAP
--------------------------------------------------------------------------------

F-01 [CRITICAL] Master admin key hardcode di client-side JS
  Lokasi   : /superadmin (HTML inline script)
  Baris    : 724, 772, 786
  Kode     :
             if (adminKey === 'siro123admin') { unlockAdminView(); }
  Dampak   : Siapa pun yang membuka halaman /superadmin (atau melihat source
             HTML-nya) mendapat seluruh kredensial admin.
  Bukti    : key diterima farm-api & mail-api dengan header X-Admin-Key.
  Rekomendasi:
             - Hapus cek key dari client.
             - Ganti dengan session token dari endpoint /api/admin/login
               yang memverifikasi password admin di server.
             - Rotasi key segera.

F-02 [CRITICAL] Alias deployment Vercel tanpa proteksi checkpoint
  URL      : https://siroheree-web.vercel.app
  Bukti    : GET / -> 200, GET /superadmin -> 200
             vs https://www.siroheree.com/superadmin -> 403
             header x-vercel-mitigated: challenge
  Dampak   : Seluruh Vercel Security Checkpoint bisa dilewati dengan
             mengakses alias deployment. Bot protection menjadi tidak berguna.
  Rekomendasi:
             - Hapus alias .vercel.app di project settings.
             - Aktifkan Vercel Deployment Protection untuk semua environment.

F-03 [CRITICAL] Tidak ada otorisasi server-side pada endpoint admin
  Endpoint : /api/admin/* pada mail-api dan farm-api
  Bukti    : Header X-Admin-Key: siro123admin -> seluruh endpoint 200
             Header admin tidak memverifikasi user, role, IP, maupun session.
  Dampak   : Siapa pun dengan key mendapat kontrol penuh tanpa audit trail.
  Rekomendasi:
             - Ganti key statis dengan token per-admin, HMAC-signed request,
               atau JWT jangka pendek berisi user_id + role.
             - Catat setiap operasi admin ke tabel audit.

F-04 [CRITICAL] Password user dapat ditimpa via admin endpoint
  Endpoint : POST /api/admin/users/{id}/update
  Body     : {"password":"<apapun>"}
  Bukti    : {"ok":true}, lalu login dengan password baru -> 200 + token valid
  Dampak   : ACCOUNT TAKEOVER. Penyerang bisa login sebagai user mana pun.
  Rekomendasi:
             - Pisahkan "change password" (wajib password lama) dari
               "admin reset" (butuh reset token satu kali).
             - Wajib re-autentikasi admin untuk operasi sensitif.
             - Emit audit event setiap reset.

F-05 [CRITICAL] Rotasi key tidak terkoordinasi antar layanan
  Key      : `siro123admin` dipakai di:
             - mail-api.siroheree.com
             - farm-api.siroheree.com
             - panel web superadmin
  Dampak   : Rotasi satu layanan merusak layanan lain; key tak pernah bisa
             dirotasi tanpa downtime.
  Rekomendasi:
             - Pisahkan key per layanan.
             - Gunakan key management / secret store.

F-06 [HIGH] Field `kind` voucher tidak divalidasi (resource abuse)
  Endpoint : POST /api/admin/vouchers
  Body     : {"kind":"<bebas>","max_emails":N,"days":N}
  Bukti    : kind="admin" -> {"kind":"admin","max_emails":1000,"days":3650}
             Setelah register: 1000 mailbox, aktif sampai 2109009929 (2036)
  Dampak   : Siapa pun dengan admin key bisa membuat akun 1000 mailbox
             berkali-kali. Operasi legitimasi user jadi rusak.
  Rekomendasi:
             - whitelist kind ke {trial, vip}
             - turunkan max_emails/days dari kind, bukan dari body
             - rate-limit pembuatan voucher

F-07 [HIGH] Tidak ada session expiry / rotation
  Bukti    : register -> token A, login -> token B, login -> token C
             Ketiga token tetap valid untuk GET /api/me -> 200
  Dampak   : Token dicuri = akses permanen sampai logout. Password bocor =
             bisa membuat token baru tanpa batas.
  Rekomendasi:
             - Session expiry 30 hari rolling.
             - Rotate token setiap login, revoke token lama.
             - Revoke semua token saat change password.

F-08 [HIGH] `expires_at` bisa di-set sampai tahun 2100
  Endpoint : POST /api/admin/users/{id}/update
  Body     : {"expires_at":4102444800}
  Dampak   : Masa aktif akun jadi abadi.
  Rekomendasi:
             - Batasi maksimum 5 tahun.
             - Hitung ulang dari plan aktif.

F-09 [HIGH] `max_emails` dapat diubah menjadi clamp 1000
  Endpoint : POST /api/admin/users/{id}/update
  Body     : {"max_emails":99999}
  Hasil    : {"ok":true,"user":{"max_emails":1000}}
  Dampak   : Akun apa pun bisa dinaikkan ke 1000 mailbox.
  Rekomendasi:
             - Batasi berdasarkan plan.
             - Perlu approval untuk kenaikan.

F-10 [HIGH] `/api/mailboxes` POST bersifat upsert (tidak cek konflik)
  Endpoint : POST /api/mailboxes
  Body     : {"address":"<nama>"}
  Bukti    : Kirim dua kali -> 201 dua kali
  Dampak   : Bisa menimpa/menduplikasi address (menyebabkan takeover inbox
             jika ada user yang sama-sama klaim address).
  Rekomendasi:
             - INSERT ... ON CONFLICT DO NOTHING.
             - Return 409 jika address sudah dipakai user lain.

F-11 [MEDIUM] Error 500 pada body JSON `null`
  Endpoint : POST /api/register, /api/login, /api/admin/vouchers
  Bukti    : body null -> 500 {"error":"Server error"}
  Dampak   : Exception tidak tertangani; menunjukkan parser tidak memvalidasi
             tipe sebelum akses field.
  Rekomendasi:
             - Validasi tipe payload (Zod, Joi, atau loop key map).

F-12 [MEDIUM] `/api/health` menerima semua HTTP method
  Bukti    : GET/POST/PUT/DELETE/PATCH /api/health -> 200
  Dampak   : Persepsi bahwa ada endpoint lain yang juga wildcard. Indikasi
             routing tidak ketat.
  Rekomendasi:
             - Batasi GET/HEAD.

F-13 [MEDIUM] Response admin tidak jujur soal field yang tidak diaplikasikan
  Endpoint : POST /api/admin/users/{id}/update
  Bukti    : {"username":"hijacked"} -> {"ok":true, user tetap Caelion21}
             {"is_admin":true}          -> {"ok":true, role tidak berubah}
  Dampak   : Otomasi admin bisa salah asumsi "berhasil".
  Rekomendasi:
             - Return 400 untuk field tidak dikenal.
             - Return state akhir yang benar.

F-14 [MEDIUM] `DELETE /api/admin/messages/0` selalu 200 `{"ok":true}`
  Bukti    : id 0, -1 -> kadang 404, kadang 200
  Dampak   : Silent success palsu; bisa menghapus pesan id=0 jika ada.
  Rekomendasi:
             - Batasi id > 0, return 400 kalau invalid.

F-15 [MEDIUM] Farm-api fallback wildcard 200 untuk semua route
  Bukti    : GET /api/apapun -> 200 {"status":"ok","service":"SIRO Farm..."}
             Ini bukan handler asli, tapi status page.
  Dampak   : Enumerasi route lewat HTTP status tidak dapat dipercaya.
             Auditing keamanan menjadi sangat sulit.
  Rekomendasi:
             - Return 404 untuk route tak dikenal.
             - Tambah header khusus untuk status page.

F-16 [LOW] Header admin menerima spasi ekor
  Bukti    : X-Admin-Key: "siro123admin " -> 200
  Dampak   : Input hygiene longgar.
  Rekomendasi:
             - Bandingkan tanpa trim(), atau pakai constant-time compare.

F-17 [LOW] Nilai key case-sensitive, tapi test portabilitas rendah
  Bukti    : "SIRO123ADMIN" -> 401
  Catatan  : Bukan bug, hanya catatan bahwa ada perbedaan nilai.

F-18 [LOW] Rate limiter login per-IP (bukan per-akun)
  Bukti    : 8 percobaan fail -> 429. Setelah 11 menit, masih 429.
             Begitu diganti username, tetap 429 (sebelumnya).
  Dampak   : Satu IP bisa mengunci seluruh akun; user di belakang NAT yang
             sama saling mengunci.
  Rekomendasi:
             - Rate limit per (IP, username).
             - Window lebih pendek (5 menit).

F-19 [LOW] `/superadmin` menampilkan form login palsu di domain publik
  Bukti    : www.siroheree.com/superadmin -> checkpoint.
             siroheree-web.vercel.app/superadmin -> 200 form.
  Catatan  : Stealth UI, tapi bukan kontrol keamanan.

F-20 [LOW] `siro-shield.js` hanya blokir devtools/F12
  Bukti    : curl / view-source tetap berhasil
  Catatan  : Bukan kontrol keamanan; membuang-buang resource.

F-21 [INFO] Email Roblox user_id leak
  Bukti    : verify_url berisi user_id 11790713298, 11041344448, dst
  Dampak   : Bisa memetakan akun Roblox yang memakai domain email ini.
  Rekomendasi:
             - Tidak perlu diperbaiki; email memang begitu.

F-22 [INFO] Domain sangat baru — kurang dari 1 bulan
  Bukti    : whois creation 2026-10-15
  Catatan  : Konteks untuk user (bukan bug).
